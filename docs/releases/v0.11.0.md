## Summary

The router can forward to a gateway instead of `chatgpt.com`. Use it when your organization sends Codex through a managed gateway and you still want the router to pick model and effort.

## Changes

- New `proxy.upstream` config field: an `https` URL for the backend the proxy forwards to. Unset keeps `https://chatgpt.com/backend-api/codex`. Credentials, query and fragment in the URL are rejected. It applies to the launcher, `codex-router proxy` and a set-up home's edge service.
- The provider check now names the provider Codex chose, for example `codex did not select the router provider (got "gateway")`.
- New guide section, [Use a managed gateway](https://github.com/alexei-led/codex-router/blob/v0.11.0/docs/user-guide.md#use-a-managed-gateway).

## Upgrade

1. Nothing is required. Without `proxy.upstream`, behavior is unchanged.
2. To use a gateway, set `proxy.upstream` and restart routed sessions. A set-up home's edge service also needs a restart. The gateway receives your ChatGPT credentials, so set only a host your organization approves.
3. Managed configuration that forces `model_provider` still overrides the router. The launcher falls back to plain Codex. Ask your administrator to leave that key unset.
