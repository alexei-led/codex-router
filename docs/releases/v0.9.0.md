## Summary

Routing modes let you trade cost for quality without editing routes: `cost`, `balanced` (the default, unchanged from v0.8.0) and `quality`.

## Changes

- `cost` moves each tier to the cheaper model one tier down, or one effort step down. It never goes below the `low` tier. `quality` moves one effort step up, or to the tier above. `micro` and pinned turns keep their routes. A mode's move, back to `balanced` included, waits for the same votes, cache cost, dwell and passed check as a tier switch. While it waits, `quality` still never runs weaker than `balanced`, nor `cost` stronger.
- Set a mode in the config (`mode`), per repository in `.codex/router.json`, or per session with `s` in the panel or `codex-router ctl mode`. A session override survives restarts and `codex resume`; a new session starts without one. `default` clears it.
- The panel, `ctl status` and the decision log show the mode and where it came from.
- `ctl` run inside Codex's sandbox now reports `cannot reach the router`, so the plugin skill asks to run it outside the sandbox.
- A repository's `.codex/router.json` must be a regular file of at most 4 KiB. A symlink, pipe or device is refused, so a cloned repository cannot stall or exhaust the router.
- The `cost` and `quality` policy values are untuned. With the default routes, `quality` on high work runs Sol at `xhigh`, which earlier evaluation found no better than `high`.
- Evidence:
  - Balanced decisions match v0.8.0 exactly.
  - A 240-cell decision matrix checks that cost never spends more than balanced and quality never less.
  - In one live four-turn task per mode, all three runs passed their tests. Router spend: cost $0.009, balanced $0.108, quality $0.117.
  - The home-mode live run was skipped; a test covers it.

## Upgrade

1. Before upgrading, replace `"preset": "thrifty"` with `"mode": "cost"` and `"preset": "quality"` with `"mode": "quality"`, and delete `"preset": "balanced"`. A config that still has `preset` fails to load, and the router runs plain `codex`.
2. A home-wide preset picked in the panel is not carried over. Set `mode` in the config instead.
3. After installing, restart the home's services and every running `codex-router` launcher. Running processes keep the old code, and a v0.8.0 panel cannot set modes.
