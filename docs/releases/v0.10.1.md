## Summary

Detect provider overrides at startup and avoid charging measured context for its serialized history again.

## Changes

- The launcher verifies Codex's effective provider before starting the TUI. If native or managed configuration overrides `router`, it explains the mismatch and falls back to plain Codex.
- Context estimates reuse measured prefixes plus appended content. Changed history or request settings, compaction and mismatched responses keep conservative fallback behavior.
- Supported effort-only changes on the current model are no longer blocked by a smaller catalog base window. Cross-model fit and compatibility checks remain enforced.
- Request correlation prevents late replies from measuring a newer request. Retry identity includes full content, and decision logs expose numeric fit inputs without request text.

## Upgrade

1. Close routed sessions, then update both the executable and plugin. Running launchers retain their old code.
2. If provider verification fails, resolve the native provider setting through your approved configuration process, then start a fresh thread. Updating the router does not override managed policy.
