## Summary

The classifier separates a task's goal from its current phase. A code goal can stay code through tests and commit, while a bounded verification or execution phase can target the existing ops route.

## Changes

- System One and OpenAI Decisions ask for goal and phase together. The existing `activity` answer remains the goal, so activity configuration stays compatible. Only supported verify/execute phases target ops; existing confidence, cache, dwell, safety and eligibility checks still apply.
- The panel distinguishes goal, phase and effective route activity. Command use alone no longer promotes a turn to an ops activity.
- A bounded, in-memory goal anchor helps identify continuations independently of recent dialogue. The classifier receives it as task data; it is not saved in router state.
- The default Jev model is `jev-1.14.0`. TypeSafe reports its largest improvement in multilingual support and introduces an experimental Box type; this router does not use Box. These claims do not establish routing-quality gains.
- Ollama has no phase answer and keeps goal-based routing. Classifier answers can still be wrong; the synthetic tests are not a representative quality evaluation.
- Require Go 1.27.4 or newer for builds, fixing [GO-2026-6859](https://pkg.go.dev/vuln/GO-2026-6859), an HTTP/1 server crash caused by a `net/http` MaxBytesReader header race.
- Built-in Standard prices are unchanged, checked against OpenAI on 2026-11-13. Cache-write prices remain outside the estimate.

## Upgrade

1. Close routed Codex sessions, replace the binary and start Codex again. Rerun setup for a set-up home as described in the [update guide](https://github.com/alexei-led/codex-router/blob/v0.12.1/docs/user-guide.md#update-or-uninstall).
2. Update the Codex plugin to 0.12.1. Existing explicit classifier and activity settings remain yours; an explicitly pinned Jev version does not change automatically.

3. For source builds, use Go 1.27.4 or newer before building to avoid the vulnerable standard library.
