Selected UI: Codex footer + router panel

This page shows how the router appears in any terminal, with no agterm code. When the router picks a new model, it writes it into the thread settings of the session's private app-server. Codex's own footer (model-with-reasoning, context-window-size) then repaints with the routed model. The router panel to the right copies the claude-model-router /router pane. Its Now tab follows the 1.13.0 layout: next turn, activity, why, pin next, SESSION, TODAY and WORTH A LOOK, then context and cache. Proxy-specific additions: the per-step "This turn" line, switch cost in uncached tokens, and the footer-sync line.

REAL · semanticsMid-turn vs next turnThe proxy switches the model per step. The footer follows the decision immediately. The setting takes effect natively from the next turn, when Codex re-resolves the window and compaction for the routed model. Not yet verified: the footer repaint while a turn is running.
REAL · manualUser /modelThe user's own model change also arrives as thread/settings/updated. The router compares it with the last value it wrote. A mismatch is the user's choice, so routing holds that model until the user resumes routing.
OURSRouter panelA separate TUI process connected to the router over a 0600 unix socket. Run it in a second terminal window or any multiplexer split. Tabs and controls match /router: pin the next turn, pause (pass-through), and policy preset.

Notes

  • Launcher codex-router: start the proxy and health-probe it, then start a private codex app-server --listen unix://… with the router provider, then codex --remote unix://…. The shared daemon and config.toml stay untouched.
  • The hook line is off by default. When on, it prints only on a model switch, as ↳ Hook · router: …, for transcripts and other clients.
  • Open checks before building: two clients on one unix app-server; a --remote TUI against an embedded one; the footer repaint during a running turn.
